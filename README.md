# MediaFetch

Веб-приложение для загрузки видео по URL. Одностраничный интерфейс, локальный HTTP-сервер (FastAPI), загрузка выполняется через yt-dlp с последующей сборкой потоков FFmpeg.

## Требования

- Windows / Linux / macOS
- Python 3.10+
- [`uv`](https://docs.astral.sh/uv/) либо pip
- Доступ в интернет

FFmpeg отдельно устанавливать не требуется: используется пакет `imageio-ffmpeg`, при наличии системного ffmpeg он имеет приоритет (поиск по `PATH`).

## Запуск

Вариант 1 — через uv (все зависимости берутся из метаданных скрипта `app.py`):

```
run.bat
```

или

```
uv run app.py
```

Вариант 2 — через pip:

```
pip install -r requirements.txt
python app.py
```

Сервер поднимается на `127.0.0.1`, порт выбирается автоматически начиная с 8000. После запуска браузер открывается автоматически.

## Структура проекта

```
app.py             — сервер, логика извлечения информации и загрузки, HTML-интерфейс
requirements.txt   — зависимости для запуска через pip
run.bat            — точка входа для Windows
downloads/         — каталог сохранения файлов (в git не попадает)
design/            — исходный макет интерфейса
```

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | HTML-интерфейс |
| POST | `/api/info` | Извлечение метаданных: `{"url": "..."}` → заголовок, длительность, обложка, список форматов |
| POST | `/api/download` | Запуск загрузки: `{"url", "quality", "format_ext"}` → `{"task_id"}` |
| GET | `/api/progress/{task_id}` | Прогресс задачи |
| GET | `/api/files` | Список файлов в `downloads/` |
| GET | `/api/download_file/{filename}` | Отдача файла браузеру |
| POST | `/api/open_folder` | Открытие каталога `downloads/` в файловом менеджере |

Значения `quality`: `best` (максимальное качество), `audio_mp3` (извлечение аудио 320k), `res_<height>` (ограничение по разрешению). `format_ext` — целевой контейнер (`mp4` и т.п.).

Статусы задачи в `/api/progress/{task_id}`: `starting`, `downloading`, `retrying`, `processing`, `finished`, `error`.

## Поведение при сбоях загрузки

Длинные видео на CDN-хостах часто рвутся по таймауту. Защита от этого задана константами в `app.py`:

| Константа | Значение | Назначение |
|---|---|---|
| `SOCKET_TIMEOUT` | 30 | таймаут сетевого чтения, сек |
| `HTTP_CHUNK_SIZE` | 10 MiB | скачивание частями по Range; обрыв теряет только текущую часть |
| `retries` / `fragment_retries` (yt-dlp) | 10 | встроенные повторы на уровне соединения и фрагментов |
| `DOWNLOAD_ATTEMPTS` | 4 | внешние попытки всего задания с докачкой `.part`-файла |
| `RETRY_PAUSE_SECONDS` | 5 | пауза между внешними попытками |

Между попытками прогресс сохраняется, статус задачи меняется на `retrying`, интерфейс показывает номер попытки. Ошибки, при которых повтор бессмыслен (`Unsupported URL`, недоступное видео, недоступный формат), не повторяются.

## Ограничения

- Работает только с теми сайтами, которые поддерживает yt-dlp (1800+ источников), плюс прямые ссылки на `.mp4`, `.webm`, `.m3u8`, `.mpd` и страницы с тегом `<video>`.
- Плейлисты не скачиваются (`noplaylist`).
- Сервер слушает только `127.0.0.1` и не предназначен для раздачи по сети.
